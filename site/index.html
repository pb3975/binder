A library for the pages your agents build.

Agents make explainers, diagrams, dashboards, and reports. Most end up lost in a thread or a temp folder. Binder is a small, self-hosted server that files them by project, keeps every version, and shows each one in a sandbox.

Quick start Source on GitHub

MIT licensed. One container. No account to create.

One request to publish.

Any agent that can run curl can publish. There is no SDK, no MCP server, and nothing to install on the agent's machine.

Teach an agent once. Copy the skill folder into the agent's skills directory, or tell the agent to read /llms.txt on your Binder. Both give the same steps.

One file or a folder. A single HTML file becomes index.html. For a folder, send one part per file, and relative links keep working.

shell
export BINDER_URL=http://localhost:8480 BINDER_TOKEN=bnd_...   # make a separate token per agent
echo '<h1>Hello, Binder</h1>' > hello.html
curl -fsS "$BINDER_URL/api/artifacts" -H 'X-Binder: 1' -H "Authorization: Bearer $BINDER_TOKEN" \
  -F 'meta={"id":"hello","title":"Hello","project":"demo","note":"First version"}' \
  -F 'file=@hello.html'
response
{
  …
  "version": 1,
  …
  "url": "http://localhost:8480/a/hello",
  "content_url": "http://localhost:8480/c/hello/1/1795377600.2ZTEc137…/index.html",
  …
}

Every version kept.

Publish the same id again and Binder makes a new version. History records who published it, when, their note, and which files changed. Open any old version, restore it, or download it.

Restore copies an old version forward, so history only grows. Removal is a soft delete.

Untrusted HTML stays in its box.

An agent can copy content from anywhere, so Binder treats every page as untrusted. Each page runs in an opaque origin. It cannot read Binder, your session, or other pages, and it cannot publish or delete anything.

Read the threat model

Content-Security-Policy: sandbox
Sent with every artifact file. The page gets an opaque origin with no cookies and no storage.
/c/<id>/<version>/<expiry>.<signature>/
Files are served only from signed URLs. Each one grants read access to one version for a few hours.
X-Binder: 1
Required on every write. A sandboxed page can send it only after a CORS preflight, and Binder never approves one.
21 attacks, 0 connections
With previews on, Chromium renders each page behind a pinned wrapper and a network allowlist. CI runs 21 attacks against it and expects zero connections.

For one person or a team.

Pick how people sign in with one setting. Agents use tokens in every mode.

Runs with Docker Compose, plain docker run, or Bun. On a host with no disk, such as AWS Fargate, files go to S3.

Values of BINDER_AUTH
BINDER_AUTHWho signs in, and how
token defaultEach person and each agent gets a named token. History records who published each version.
oidcPeople sign in with your identity provider, such as Keycloak, Okta, Entra ID, or Google. Binder never stores a password.
headerBehind Tailscale or another identity-aware proxy, Binder trusts the proxy's user header, and only from the proxy's address.
noneNo sign-in, for one person on a laptop. Binder answers only requests addressed to localhost.

Small enough to read in an afternoon.

One Bun process, one SQLite file, one data folder. No runtime dependencies and no build step. Backup is a folder copy.

Binder is not a CMS. It has no comments, no real-time editing, and no public sharing.

data/
binder.sqlite        artifacts, versions, tokens
secret.key           32 random bytes, created on first start
versions/<id>/<n>/   the files of version n, immutable after publish
thumbs/<id>.png      preview of the current version

Start in three commands.

You need Docker.

shell
git clone https://github.com/pb3975/binder && cd binder
docker compose up -d
docker compose exec binder binder token create --name you

Open http://localhost:8480 and paste the token.
